# 0.4.3 开机自启动

用户需求：给当前应用增加自启动；保持设置简洁，不影响正在使用的电脑。

## 实现范围

- 设置增加“开机自启动”，点击保存后生效；取消不修改启动项。默认不登记。
- 使用当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `LightCapture` 值，无需管理员权限。启动命令为带引号的当前完整 EXE 路径和 `--autostart`。
- 关闭开关只删除本应用启动值。设置页读取登记值，不在 JSON 重复存储开关状态；保存开启状态时刷新旧路径。
- 自动启动进入托盘，不显示欢迎提示或设置窗口；已有实例时直接退出，不发送截图信号。手动重复运行仍保留原有截图行为。
- 写入启动项或保存设置失败时恢复此前快捷键及启动项，恢复失败明确显示错误。
- 不增加安装器、账号注册、服务或计划任务。

## 使用

将完整应用目录放在固定位置，运行 `LightCapture.exe`，右击托盘 → 设置 → 勾选“开机自启动” → 保存。下次登录 Windows 生效。移动文件夹或切换版本目录后，打开新目录中的程序，再保存一次开启状态以刷新路径。

如在 Windows 任务管理器中禁用了该启动项，需在那里重新启用；应用开关表示是否登记启动项，不覆盖 Windows 的禁用策略。

## 验证边界

使用内存启动项替身检查保存、取消、错误回退与命令路径；后台自测不写实际启动项、不启动前台窗口、不注册实际热键。真实注销/登录启动尚未执行，以免打断用户工作。

验证结果：20 项核心测试、7 项 Python 测试、19 项原生后台检查通过。设置页在 100% / 125% 比例离屏渲染，未打开交互窗口。

启动机制与 260 字符命令长度约束依据 [Microsoft Run / RunOnce 文档](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)。

只读审查：Standards 轴 0 项确认问题；Spec 轴 0 项确认问题。真实登录和重复实例交互未执行，结论限于代码检查及后台测试。
