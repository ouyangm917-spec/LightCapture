# 0.4.4 GIF 录制缓存修复

用户在 0.4.3 开始 GIF 录制时反复遇到 recordings 会话目录访问被拒绝。已确认旧代码直接创建目录并终止，操作系统拒绝访问的具体来源尚未确认；本次不修改 ACL 或要求管理员运行。

## 修改范围

- 默认缓存仍为用户数据目录下 recordings。开始录制前，在本次随机会话目录中实际写入、读取并删除验证文件。
- 默认位置不能创建或读写时，尝试 `%TEMP%\LightCapture\recordings`，使用独立会话子目录。两处都不可用时显示中文原因和两个目录。
- 录制中权限或磁盘状态改变导致帧写入失败时显示中文提示；不迁移已录帧或无限重试。
- 成功关闭、取消或失败后只清理本次会话目录，不扫描或删除其他录制。目录再次拒绝删除时保留原有尽力清理行为，不修改权限。
- 已取消的任务不创建缓存或截屏。截图、贴图、翻译、自启动、GIF 导出参数均不变，无数据库和公开接口变更。

## 验证范围

后台使用合成帧和隔离测试目录，验证正常主目录、拒绝访问回退、两个目录均失败、备用路径 GIF 导出、预先取消、中途写入失败与独立清理。不操作用户桌面、当前运行应用、真实缓存或系统权限。真实桌面录制与现场安全策略仍需用户启动新版后确认。

验证结果：20 项核心、7 项 Python、21 项原生后台检查通过。Standards 与 Spec 两项只读审查均未发现确认问题；真实桌面录制未执行。
